# Serie propuesta — decisiones de un proyecto de Data Engineering

El primer artículo aborda solo la granularidad. No publica todo el proyecto de una vez ni presenta etapas pendientes como terminadas.

Versiones del artículo: [English](01_article_en.md) y [Español](01_article.md).

| Entrega | Tema | Evidencia del proyecto |
|---|---|---|
| 1 | Apariciones frente a negocios: definir el grano antes del dashboard | 315 respuestas → 3.272 apariciones → 1.314 establecimientos |
| 2 | NULL no es cero ni false | 303 conteos no reportados y ausencia de ceros explícitos |
| 3 | Reejecutar sin duplicar | Claves de consulta, manifest, persistencia, MERGE y guardas de contenido; explicar límites ante fallos de red |
| 4 | La media y la mediana cuentan historias distintas | Bares: media 158,01 frente a mediana 14,5; acompañar con distribución |
| 5 | Categoría de búsqueda frente a categoría de análisis | Clasificación principal y puente de detecciones |
| 6 | De ejecución manual a Job | Publicar después de implementar y validar la orquestación |

El artículo y el post corto son dos formatos del primer tema: usar el post como anuncio del artículo o como publicación independiente. No es necesario publicar ambos textos completos el mismo día.

Si se acompaña con una imagen, puede ser un diagrama de los tres granos o una captura real del control de reconciliación. No usar una captura ficticia como evidencia de ejecución.

Antes de publicar: leer el texto en voz propia, mantener explícito que es un proyecto de aprendizaje y verificar que el repositorio enlazado esté listo para recibir visitas. Los textos son borradores; esta revisión no publicó contenido en LinkedIn.
